# SOP: Session Hand-Off & Project Synchronization


## Phase 1: Code Demotion & Archival

Before cataloging new work, clear the workspace of legacy or deprecated code. Silent deletions are prohibited.

* [ ] **Archive Monolithic Scripts:** Move any lingering single-file session scripts (e.g., `mpc_session*.py`) into the `historical/` subdirectory.
* [ ] **Relocate Demoted Packs:** If a pack was replaced or retired during this session, move its folder to `mpc_packs/deprecated/`. It must remain there for at least one revision.
* [ ] **Update Deprecation Notes:** Add a deprecation note to the `README.md` of any demoted pack, explicitly stating why it was demoted and pointing to its replacement.

## Phase 2: Pack Extraction (Prototype to Pack)

Any inline session code that provided a reusable capability must be extracted into a standalone pack.

* [ ] **Identify Promotable Code:** Locate any prototype code that was successfully used end-to-end and interacts with the kernel exclusively through one of the three plug points: `SubstrateExtension`, `EventSubscriber`, or `Governor`.
* [ ] **Create Pack Directory:** Create a new folder at `mpc_packs/<pack_name>/`.
* [ ] **Scaffold Required Files:** Ensure the new directory contains exactly the following:
    * `__init__.py`
    * `pack.py` (The capability's code).
    * `config.py` (The configuration dataclass, including all declared dependencies on other packs).
    * `test_pack.py` (A regression test exercising the `attach -> use -> detach` cycle).
    * `README.md` (Documenting interfaces, dependencies, and status).
* [ ] **Verify Namespace Isolation:** Check that the pack defines its own event types and data structures rather than modifying or shadowing kernel types.

## Phase 3: Experiment Containerization

The session you just completed is now permanently classified as an "Experiment". It must be cleanly boxed up.

* [ ] **Create Experiment Directory:** Create a new folder at `experiments/<experiment_name>/`.
* [ ] **Isolate Execution Logic:** Move the session's driver code (e.g., the maze generator or specific test runner) into `experiments/<experiment_name>/run.py`.
* [ ] **Generate Manifest:** Create `experiments/<experiment_name>/manifest.py`. This must explicitly declare:
    * The kernel version required.
    * The complete list of packs loaded, alongside their configurations.
* [ ] **Write the Report:** Draft `experiments/<experiment_name>/report.md`. Ensure it includes:
    * Final Results table.
    * Per-component sections.
    * RFC-001 invariant checklist.
    * List of artifacts generated.
    * Outstanding issues/open items.
* [ ] **Store Artifacts:** Move all output plots (`*.png`), traces (`*.json`), and logs generated by the session into `experiments/<experiment_name>/artifacts/`.

## Phase 4: Prepare the Next Session

With the previous session cleanly archived and componentized, initialize the starting state for the next experiment.

* [ ] **Lock Kernel Version:** Declare the exact semantic version (MAJOR.MINOR.PATCH) of the kernel that will be used for the next session.
* [ ] **Establish Target Manifest:** Define the baseline packs required. Unless disabled, this defaults to the standard manifest (e.g., `JAXSubstrate`, `AutoCluster`, `Effector`, `Calorimeter`). 
* [ ] **Define the Domain/Workload:** Document the specific task, workload, or problem domain the next session is meant to solve before writing new execution code.
